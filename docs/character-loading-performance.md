# 长章节加载优化（2026-11-09）

逐字审核的章节分块由 512 KiB 改为 128 KiB，沿用四路并发与有界重试。269 章的原始 JSON 字节、原 gzip 压缩包字节、字符映射、正文／原图 SHA 及草稿绑定均保持。新分块按内容 SHA 命名；旧分块保留，兼容缓存中的旧目录。可使用 `python3 scripts/rechunk-character-data.py` 重新生成并核验，当前共 560 个分块。

新增 Zstandard 快速传输，完整原始章仍由同一个 SHA 校验；全书压缩体积从 50,941,363 降到 26,722,025 字节，最长附录从 8,616,772 降到 3,459,576 字节。原 gzip 传输保留供旧程序使用；新程序优先复用已存在的 gzip 缓存，避免重复下载。浏览器使用同站点托管的 MIT `fzstd@0.1.1` 解压器，版本、许可证和来源见 `proofread/vendor/`；不从外部 CDN 加载。

构建使用 Node.js 24 的 `node scripts/build-character-zstd.mjs`。每个压缩包显式写入原始大小，浏览器先检查长度上限再解压。使用解压器自身分配，避免该版本传入大输出缓冲区时发生类型转换、造成 WebKit 内存峰值。构建逐章使用同一浏览器解压器核对原始 SHA，最长章节另用禁止大数组字符串转换的双浏览器回归验证。页面预加载解压模块，缩短模块依赖的请求等待。

已核验的整章压缩数据保存在独立的 `shulun-character-transport-v1` IndexedDB 中，写入事务完成后才视为缓存可用。再次打开时校验压缩 SHA、长度及解压后的原始章 SHA，仍不省略正文版本检查。最近使用数据在同一写入事务内淘汰，上限 20 MiB。数据库仅含可重新下载的传输数据，与人工正文草稿、调框、审核记录及来源数据库独立；不迁移或覆盖任何人工状态。缓存损坏、被清理、不可用或配额不足均可退回正常网络载入。

目录与加载程序版本同步更新，避免浏览器继续引用旧分块清单。未改变整章审核、文字输入、字图裁剪及保存模型。

发布前验证：269 章重新分块后全部字节及 metadata/binding 保持；网站 541 项 Node、89 项 Python 与构建检查通过；Chromium／WebKit 的 26 项原文校对回归、12 项真实缓存／配额／淘汰／损坏恢复检查及 2 项最长附录加载检查通过。缓存测试在禁止字块网络请求时重新载入长章节，并核对原有本机记录。浏览器测试不构成实体输入法验收。

基线实测《述书赋上》12,120 字首次正文可用约 16.4 秒，首批字图约 19.7 秒；该单次结果受网络影响，不能视作所有用户的固定耗时。发布后冷／热加载耗时及正式资源核对另存工作区 `tasks/2026-11-09-character-loading/`。

回退时恢复上一版本的目录及加载程序即可；旧分块仍可用，人工草稿无需变更。

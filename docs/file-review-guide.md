# 文件收发审核版

更新：2026-09-27。复查：2026-10-04。

## 使用流程

独立入口：`review.html`。发布地址：https://sisatrek-oi.github.io/calligraphy-online-site/review.html 。无需服务器账号、OCR 或模型服务；实际发布状态以 GitHub Pages 构建与访问验收记录为准。

### 负责人

1. 在完整工作台准备待审核条目和原文页，在材料管理工具中点击“导出审核材料”。也可使用已有“导出工作区”生成的 JSON。只有原文、没有条目的工作区不能发起审核。
2. 打开文件审核页，“发起与汇总”导入上述 JSON，填写批次名称和成员姓名（每行一个）。初始提供五个可修改的成员名称。
3. 核对原文是否齐全；需要查看原图时，为对应条目附加 PNG/JPEG/WebP。单图最多 4 MB；同一原文文件的条目共用所选图。未附原文不能声称已核实出处。
4. 创建批次，先下载并保管“协调备份”，再把各人的“审核包”分别发给本人。本版每名成员审核这批全部条目；要分工可另建小批次。
5. 回收成员导出的结果 JSON，在该批次“收回审核结果”中导入，可多选。核对姓名、收回人数及分歧。
6. 下载汇总 CSV 和最新协调备份，人工处理分歧。系统不自动改原主表，也不把一致通过直接当作最终研究结论。

### 审核成员

1. 打开同一网页，在“我是审核成员”导入自己的审核包。核对页首姓名与材料标题。
2. 对照原文／页图和原字段；可改写建议字段，选“通过”“需要修改”或“无法判断”。后两项必须说明理由，改了字段就应选“需要修改”。
3. 点击“保存本条并继续”。输入也会自动保存草稿，留意顶部保存状态；用“下载草稿备份”转移设备或留底。
4. 所有条目完成后，点“生成结果文件”，再点“下载审核结果”，把这个结果文件发回负责人。只保存草稿不会自动提交。
5. 如需重交，修改后重新生成结果，版本号递增；发回最新文件。负责人保留旧版并显示最新版。

## 下载没有反应时

每个文件按钮旁都有“复制内容”。打开后点击“复制全部内容”，在文本编辑器中以纯文本保存为页面给出的文件名（保留 `.json` 或 `.csv` 扩展名，UTF-8 编码）。复制失败时文本自动选中，可按 Ctrl+C／Mac ⌘C。JSON 文件再次导入会校验格式和材料指纹。

本次 Codex 内置浏览器未返回原生 Blob 下载完成事件，因此未把一键下载记为实机通过。可见文件内容导出、保存后重新导入的闭环已验证；普通浏览器的一键下载仍需实际使用确认。

## 保存、版本与边界

- 材料在浏览器本机 IndexedDB 保存，不自动上传。清理站点数据或更换浏览器后需要导入备份；本地地址与线上地址的数据不会互通。
- 新建批次冻结材料，SHA-256 指纹用于识别错批次和误改。结果包含成员、包编号、条目、建议值、说明、版本及导出时间。
- 同一结果重复导入跳过；同版本不同内容拒绝；旧于最新版的未收版本拒绝；新版本保留旧记录。
- 两标签页编辑同一草稿时通过事务修订号拒绝过期覆盖。保存失败后提供恢复文件；先备份再刷新，勿继续假定已保存。
- 该入口不继承本地模拟账号的权限。姓名仅是分发标识，不是经过认证的身份；同一浏览器使用者可看到本机任务列表。材料与结果只发给应接收的人。
- 有分歧的条件包括判断、建议字段或说明不同；文字表达差异也可能被标记，需负责人核对。
- 任务文件最多 50 MB，最多 2000 条／80 字段／20 名成员；大材料建议拆成更小批次。图片嵌入会增加文件体积，不会把本机文件地址当作远程可访问图片。
- 审核材料导出只保留条目字段及相关原文，不包含工作区历史、回收站、账号、其他成员意见。网页代码可公开，私有材料不要提交到 GitHub。

## 验证

- 175 项 JavaScript + 77 项 Python 测试通过，共 252 项；其中 10 项为文件审核协议测试。
- 实际页面：创建五份独立包，五人分别审核，包含通过、修改、无法判断，回收显示 5/5 与 1 条分歧；原作者字段未被覆盖。
- 实际文件回读：五个结果均通过批次检查，再次合并均判重复；协调备份包含五人意见。
- 刷新保留、独立存储环境导入协调备份恢复、跨标签页过期写入拒绝并生成恢复文件均通过。
- 390px 布局宽度为 390px，审核输入区高 90px；默认桌面原文与建议并排。浏览器全页截图有拼接缩放偏差，不作为像素级验收证据。
- 未验证：真实五人不同设备联合使用、普通浏览器原生下载、满额大包性能。当前图片附件支持已实现，尚未进行大批扫描页图的真实审核验收。

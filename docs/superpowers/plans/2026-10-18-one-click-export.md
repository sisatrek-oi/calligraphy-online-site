# 一键导出实施计划

执行方式：在本聊天内按步骤执行，使用既有用户授权，不增加方案审批轮次。

**目标：** 一次点击下载一个完整且可恢复的校勘交付ZIP，随后完成两条研究方向的有据调研。

**架构：** 独立纯函数生成交付文件与清单，标准ZIP打包器输出二进制；screening页面只负责冻结快照、加载材料、下载与反馈。研究报告基于当前数据审计与一手文献单独生成，不改变参考真值。

**技术：** 原生浏览器ES模块、TextEncoder、Web Crypto SHA256、标准ZIP store/CRC32；Node测试与Python zipfile独立解压；现有CSV/校勘/进度模块。

- [ ] 1. 在`src/collation-export.js`集中生成TXT、三类CSV、候选表及原格式JSON，复用`exportText`、`metricsCsv`、`pageMetrics`、`progressSummary`；在`src/zip-store.js`实现标准ZIP。测试放`scripts/test-collation-export.mjs`。先检查导出结构、状态一致、旧底稿缺失不造值、UTF-8及独立解压、未保存标记、深拷贝不变。
- [ ] 2. 在`src/screening.js`把三个主按钮、普通备份及本页下载改为共同“一键导出全部”操作；冻结点击时payload后才异步加载，重复点击忽略；失败保持可重试，普通下载只触发一个二进制Blob。故障JSON抢救保留。全部完成提示、导入提示与团队交付说明同步。
- [ ] 3. `npm test`、`npm run check`、`git diff --check`；用本地隔离来源实际生成ZIP、解压并恢复JSON，核对修改率/编辑记录/疑字不变。浏览器通过cua工具验收主按钮、一次下载、单屏及390px布局；不运行旧Playwright脚本操作用户浏览器。
- [ ] 4. 更新操作说明/项目路线，审查白名单diff，提交、推送main、等待Pages；正式站重新下载ZIP并独立验证。截图及下载证据保存在任务`evidence/`。
- [ ] 5. 导出验收后读取既有研究方案及数据质量边界，用一手论文/标准调研文本可靠性、书论命题可验证性、OCR风险分配，以及固定模型的知识效用/误导效应；保存有引用的调研报告、当前证据矩阵与分阶段可检验方案。区分已完成数据分析与待做实验。
- [ ] 6. 按完整目标审计：一键导出实际上线且恢复可用；两个研究方向和OCR支线都有现有证据、问题定义、可执行实验/指标、失败条件与下一步。仅在全部满足后结束目标。

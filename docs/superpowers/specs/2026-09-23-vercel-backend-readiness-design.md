# Vercel 后端部署准备设计

日期：2026-09-23

## 目标

- 让仓库在 Vercel 上提供当前网页真正依赖的健康检查、公开配置、搜索、单模型抽取和三模型共识接口。
- 所有模型密钥只从 Vercel 环境变量读取，不进入前端响应、Git 或工作区数据。
- 让线上古籍入库明确显示“需要本地服务”，而不是暴露必然失败的按钮。
- 提供可复制的环境变量模板、部署步骤、冒烟检查和回滚说明。

## 非目标

- 本轮不创建 Vercel 项目、不写入生产环境变量、不触发生产部署。
- 本轮不把本地 PDF、OCR 任务或输出文件迁移到云端。
- 本轮不迁移 Supabase 数据，也不修改现有 RLS。

## 边界与数据流

1. 静态网页由 Vercel 托管。
2. `/api/config` 和 `/api/model-config` 只返回公开能力与脱敏模型信息。
3. `/api/ai/extract`、`/api/ai/consensus` 从环境变量读取密钥并直接调用兼容 Chat Completions 的模型接口。
4. 三模型请求并行执行；字段共识在函数内确定性计算，不把密钥或原始模型响应落盘。
5. 线上 AI 请求默认验证 Supabase 会话，并通过 RLS 确认请求者能读取目标云端工作区，避免暴露公开计费端点。
6. 单模型重试为无状态请求：函数签发与原文、字段模板和审核策略绑定的 HMAC 重试令牌。重试时不信任浏览器回传的模型结果，验签后只重跑指定槽位并重新计算共识。
7. Supabase 继续承担账号、团队、工作区和审校记录持久化。
8. 古籍 OCR 保持本地：Vercel 页面只解释限制，不访问本地文件系统接口。

## 环境变量

- 云协作：`SUPABASE_URL`、`SUPABASE_ANON_KEY`、`CLOUD_SYNC_ENABLED`。
- 三模型：每个槽位使用 `MODEL_<SLOT>_API_URL`、`MODEL_<SLOT>_API_KEY`、`MODEL_<SLOT>_NAME`、`MODEL_<SLOT>_FAMILY`。
- 兼容模式：旧的 `MODEL_API_URL`、`MODEL_API_KEY`、`MODEL_NAME` 仍作为 primary 回退。
- 策略：`MODEL_REVIEW_MODE=assist`、`MODEL_DEFAULT_CONSENSUS=standard`。

## 失败模式

- 缺少模型变量：公开配置准确显示未配置；AI 接口返回 503。
- 只有一个模型：单模型抽取可用，共识入口返回 503，前端不会误显示三模型已就绪。
- 上游模型超时或失败：对应槽位标记为失败，共识结果进入人工审核。
- 函数超时：Vercel 返回超时错误，前端保留原记录并显示失败，不自动写入。
- 古籍入库在线上打开：显示本地能力说明，不创建虚假任务。

## 验证

- 静态语法与 `vercel.json` 配置检查。
- 环境变量解析、脱敏响应、三模型共识、失败降级、无状态重试单测。
- 全量 Node/Python 回归。
- 本地模拟 Vercel handler 的健康检查与配置响应。
- 正式部署后再执行 `/api/health`、`/api/config`、`/api/model-config` 和网页冒烟检查。

## 回滚

- 代码问题：在 Vercel 将生产别名切回上一部署。
- 模型问题：移除或停用对应槽位环境变量后重新部署；前端自动回退到单模型或禁用 AI。
- 数据问题：本轮不修改数据库结构；停止云同步入口并保留 Supabase 数据。

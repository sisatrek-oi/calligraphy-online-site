# 古籍任务发布与分工设计（2026-09-29）

## 目标与范围

管理员按古籍发布总任务，再按页段及处理环节拆成工作项，指定成员。成员登录后仅能读取自己的已发布工作项，保存草稿、提交；管理员验收或退回。此次先在五账号本地演练服务验证完整协作闭环，不把本地演练称为生产上线。

## 已确认事实与假设

- 已确认：团队五人、平台由用户独立开发；本地模拟账号已有独立身份和存储，但没有共享任务；静态审核页向所有成员分发整批材料，姓名不是认证身份。
- 假设：用户所说“按份拆解”指按连续页段分配、每段指定 `原文校对`／`全书初筛`／`条目审核` 环节；首版由管理员指定负责人，不开放自行领取。用户若指定其他拆分法，可改变工作项定义而保留发布和提交状态机。

## 数据与权限

- 一条古籍总任务包含书名、总页数、来源说明、创建者、草稿／已发布状态和时间。不同古籍互不混合。
- 工作项包含总任务 ID、处理环节、起止页、负责人、原始材料／工作说明、状态、修订号、工作文本和时间。相同古籍、相同环节的页段不可重叠；不同环节允许同页。页段必须在总页数内。发布前需有书籍来源说明，或每个工作项均有原始材料。
- 演练账号 `test01` 是管理员，`test02`—`test05` 是工作人员。仅服务端凭会话决定角色与工作项归属；客户端传入的用户名不决定授权。
- 管理员可创建草稿、拆分工作项、发布、重新分配、验收和退回；成员只能读取自己已发布的工作项、保存自己的草稿和提交。验收后的工作项不能由成员改写。
- 每次分配、提交、退回和验收记录事件；重分配保留旧记录。成员提交的内容不会自动写入古籍主表，验收后仍由管理员决定是否入库。

## 状态与交互

`草稿总任务 → 发布`；工作项 `待处理 → 进行中 → 待验收 → 已验收`，管理员可把 `待验收` 退回成 `需修改`，成员保存修订并重交后再次 `待验收`。管理员可在未验收时改派，改派后当前草稿仍在服务端并留痕。

新页面 `team-tasks.html` 在静态预览中明确提示需要本地协作服务；在模拟服务中登录后，管理员看到任务发布与全部进度，成员看到“我的任务”。页段和环节、当前状态、负责人、修订时间在列表可见。保存失败或修订冲突不丢弃编辑框中的文字。

## 边界、回退与验收

原有古籍工作区、OCR 批次、静态文件审核包和五账号私有材料保持原样；不自动迁移或合并。新共享任务使用模拟数据目录下的独立 SQLite 表，服务器只监听回环地址。回退前端和服务代码不会删除数据库表。

验收：管理员发布两本书，同书多页段及多环节；成员只能读写自己的任务；越权、交叉页段和过期修订被拒绝；提交、退回、重交、验收、重分配可追溯；服务重启后保留状态；桌面和手机页面能完成该流程。正式团队云端部署、文件附件与自动入主表不在此次范围内。

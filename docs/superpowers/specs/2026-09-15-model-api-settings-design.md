# 模型 API 设置设计

## 目标

在现有“项目设置”中增加可实际使用的模型连接配置，让本地运行者能够测试 OpenAI Chat Completions 兼容接口、切换模型，并在重启本地服务后继续使用已保存配置。

## 范围

本次包含：

- 在项目设置中增加“字段模板 / 模型连接”页签。
- 配置接口地址、API Key 和模型名。
- 测试未保存的草稿配置。
- 在本地服务端持久保存、读取和删除模型配置。
- 保存后让后续 AI 字段理由请求立即使用新配置。
- 对纯静态部署和不支持配置写入的服务显示明确状态。

本次不包含：

- Anthropic Messages 等非 Chat Completions 原生协议。
- 把 API Key 写入浏览器存储、工作区 JSON、CSV、审校日志或云端同步数据。
- 多用户云端密钥托管、团队共享密钥、密钥计费和调用额度管理。
- 在 GitHub Pages 中直接调用第三方模型接口。

## 界面

“项目设置”继续使用现有模态窗口和视觉体系，顶部增加两个页签：

1. “字段模板”：保留现有字段模板编辑器。
2. “模型连接”：显示模型配置与连接状态。

模型连接只展示必要控件：

- 接口地址：完整 Chat Completions URL。
- API Key：`password` 输入，不预填已保存密钥。
- 模型名：发送给兼容接口的模型标识。
- “测试连接”：使用当前表单草稿发出最小请求，不保存。
- “保存配置”：验证并持久化，成功后立即成为活动配置。
- “删除配置”：二次确认后删除本地持久配置，并回退到环境变量。

已保存密钥只显示“已保存 · 尾号 xxxx”。界面不得从服务端取得完整密钥。API Key 留空保存表示沿用已有本地密钥；首次配置时留空必须报错。

按钮使用现有克制的工作台样式，不新增独立视觉语言。连接结果在表单内就地显示，不使用阻断式成功弹窗。移动端页签、输入框和操作区不得横向溢出。

## 配置模型

本地服务的有效配置按以下优先级解析：

1. `.runtime/model-config.json` 中完整且有效的本地配置。
2. `MODEL_API_URL`、`MODEL_API_KEY`、`MODEL_NAME` 环境变量。
3. 未配置状态。

本地配置文件内容为：

```json
{
  "apiUrl": "https://api.example.com/chat/completions",
  "apiKey": "secret",
  "model": "model-name",
  "updatedAt": "2026-09-15T00:00:00Z"
}
```

`.runtime/` 必须加入 `.gitignore`。写入采用临时文件加原子替换，并尽力将目录权限设为 `0700`、文件权限设为 `0600`。解析失败或字段缺失时不得静默覆盖环境变量，也不得把损坏内容返回前端。

## 服务端接口

### `GET /api/model-config`

返回公开状态，不返回完整密钥：

```json
{
  "supported": true,
  "configured": true,
  "source": "local-file",
  "apiUrl": "https://api.example.com/chat/completions",
  "model": "model-name",
  "keyHint": "xxxx"
}
```

环境变量配置可以显示 URL、模型名和密钥尾号，但浏览器不能修改或删除环境变量本身。

### `POST /api/model-config/test`

接收 `apiUrl`、`apiKey`、`model`。当 `apiKey` 为空且已有本地配置时，可沿用已有密钥完成测试。服务端向目标接口发送最小 Chat Completions 请求，并返回成功、模型名与耗时；第三方响应正文不透传。

### `PUT /api/model-config`

验证配置并写入本地文件。保存动作本身不自动调用第三方模型；用户可先测试再保存。成功响应仍只返回公开状态。

### `DELETE /api/model-config`

删除本地配置文件。若环境变量完整，响应显示已回退到环境变量；否则显示未配置。

现有 `POST /api/ai/extract` 改为使用统一配置解析函数，保证设置页显示的活动模型与实际抽取模型一致。

## 地址校验

允许：

- `https://` 公网 URL。
- `http://localhost`、`http://127.0.0.1`、`http://[::1]` 本机模型 URL。

拒绝：

- 非 HTTP(S) 协议。
- URL 中包含用户名或密码。
- 公网主机使用明文 HTTP。
- 空主机、解析失败的 URL 或超长字段。

本地配置接口仅由本地 Python 服务提供。Vercel Serverless 和 GitHub Pages 不实现文件写入；前端收到 `404`、`405` 或 `supported: false` 时显示“当前部署不支持网页配置，请使用服务端环境变量”，并禁用保存和删除，但不影响既有 AI 功能。

## 数据与安全

- API Key 仅通过同源请求传给本地服务，再由本地服务发送到用户指定的模型接口。
- 前端状态只持有用户当前输入的 Key；关闭设置或保存成功后清空该输入。
- 不使用 `localStorage`、`sessionStorage`、IndexedDB 或工作区数据保存 Key。
- 任何日志、错误消息和测试响应均不得包含 Key 或第三方完整响应正文。
- 配置不进入 Supabase、工作区导出、备份或版本历史。
- 用户从非本机地址访问本地服务时，配置写接口拒绝请求，避免局域网其他设备修改本机密钥。

## 状态与错误

模型连接区使用以下状态：

- 读取中：设置页首次打开时加载公开配置。
- 未配置：需要填写全部三项。
- 已配置：显示来源、模型、URL 和 Key 尾号。
- 测试中 / 测试成功 / 测试失败。
- 保存中 / 保存成功 / 保存失败。
- 当前部署不支持网页配置。

表单提交期间只禁用对应操作，保留用户草稿。网络错误、401/403、404、429、超时和非 JSON 响应转为简洁中文错误，不显示第三方响应正文。

## 兼容性与回滚

- 未创建本地配置文件时，现有 `.env.local` 和部署环境变量行为保持不变。
- 删除 `.runtime/model-config.json` 即可回滚到环境变量配置。
- 前端读取不到新接口时只降级模型设置区，不影响字段模板、主表和人工审校。
- 不更改工作区数据结构，不需要数据迁移。

## 验收标准

自动化测试覆盖：

- URL 校验允许 HTTPS 和本机 HTTP，拒绝其他明文 HTTP 与危险协议。
- 保存配置后公开响应不含完整 Key，文件权限和内容正确。
- API Key 留空时沿用已有本地密钥；首次保存留空失败。
- 重启配置读取逻辑恢复本地配置。
- 删除后回退环境变量或未配置状态。
- 测试连接不写文件，成功与常见失败状态均被清洗。
- AI 抽取读取统一的活动配置。
- 非本机请求不能修改配置。
- 前端不把 Key 写入浏览器存储或工作区序列化。

浏览器验收覆盖：

- 项目设置可在两个页签间切换，字段模板功能不回归。
- 配置、测试、保存、切换模型和删除流程状态明确。
- 保存后关闭再打开设置，Key 不回显，只显示尾号。
- 390x844 与桌面视口无重叠、无横向溢出、主要操作无需翻找。
- 纯静态部署显示准确的能力限制，不出现虚假成功。

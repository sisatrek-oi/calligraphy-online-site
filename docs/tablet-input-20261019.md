# 平板系统手写键盘兼容修复（2026-10-19）

用户反馈：选中正文后用系统手写键盘输入，光标错位，文字可能出现在末行开头。设备型号与浏览器未知。

已确认的代码问题：

- 触屏/笔长按触发 `contextmenu` 时，网站抢占原生菜单，并在下一帧聚焦替换输入框。隔离 Chromium、WebKit 均复现正文失焦。
- 替换输入框未区分输入法确认候选字与普通 Enter。合成期间的 Enter 会提前提交替换并把焦点移回正文。两个引擎均复现。
- 正文每次合成输入都会重建校验、页码与高亮 UI。改为保留中间稿自动保存，合成结束后再刷新这些控件；正文原生输入不回写 textarea.value，也不恢复或猜测选区。

触屏与笔长按交还系统；鼠标右键替换及原改对照历史保留。输入法合成状态及旧输入法 keyCode 229 不触发网站快捷操作。两个共享编辑器入口均更新模块版本，避免沿用旧脚本。

验证：312 项 JS、89 项 Python、`npm run check`；38 项 Chromium/WebKit 输入回归、34 项标注/校验/导出恢复回归、6 项本人交付检查通过。输入回归含原生 Chromium IME、多轮候选、80 行滚动正文第 1/40/80 行替换、保存及刷新恢复；另核查触屏/笔长按、鼠标替换历史、其他页草稿与旧比较底稿、三种视口无外层滚动。公开材料无修改，测试均使用隔离浏览器存储。

```sh
BASE_URL=http://127.0.0.1:8810 OUTPUT_DIR=/tmp/shulun-tablet-check \
  node scripts/visual-tablet-input-check.mjs
```

需提供已安装 Playwright 的 Node 环境（或设置 NODE_PATH 指向其依赖目录）。默认同时运行 Chromium 与 WebKit；报告和截图输出至 OUTPUT_DIR。

边界：未取得用户实体平板，不能将浏览器模拟称为实体手写键盘验收，也未声称复现了实体设备“末行开头”的精确现象。真实平板需看到“已自动保存到本机”后刷新/重新进入任务，再复测中间行选字手写。勿清理浏览器站点数据，个人稿沿用原存储键。发布提交、Pages 与正式资源校验见工作区 `tasks/2026-10-19-ui-redesign/tablet-input-evidence/README.md`。

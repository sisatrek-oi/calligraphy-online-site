# 单条 AI 初稿 MVP

## 目标

在条目详情中基于当前原文页和字段模板生成结构化候选，展示与现有字段的差异。模型结果不得自动覆盖主表，只有人工明确采纳后才进入审校历史并保存。

## 非目标

- 本阶段不做批量任务、自动提示词优化或模型自动确认。
- 不把模型自报概率当作证据等级。
- 不在浏览器中保存模型密钥。

## 数据流

```text
原文页 + 当前字段 + 字段提示词
  -> POST /api/ai/extract
  -> 服务端模型调用
  -> JSON 解析与字段白名单
  -> 原文证据逐字校验
  -> 前端候选差异
  -> 人工采纳
  -> 主表、审校历史、云端审校事件
```

## 配置

- `MODEL_API_URL`：兼容 Chat Completions 请求形态的服务端地址。
- `MODEL_API_KEY`：只存在于本地进程或部署环境变量。
- `MODEL_NAME`：部署方明确指定的模型名称。

未配置时 `/api/config` 返回 `aiEnabled: false`，界面明确显示“模型未配置”。

## 输出契约

```json
{
  "fields": { "author": "王羲之" },
  "evidence": [{ "fieldId": "author", "quote": "王羲之" }],
  "abstentions": [{ "fieldId": "scriptType", "reason": "原文未明确" }]
}
```

服务端只接受当前模板中的字段 ID；证据引文必须逐字存在于本次原文中，否则标记为未验证。缺乏证据时模型应弃答，不得补造。

## 风险与回退

- 原文被视为不可信数据，提示词要求忽略原文中的指令性内容。
- 请求限制原文长度和字段数量，接口错误不修改条目。
- 关闭或删除三个 `MODEL_*` 环境变量即可停用入口，不影响人工工作流。
- 当前版本只在人工采纳时保存运行元数据；完整的未采纳运行审计留给后续 `model_runs` 表。

## 验收

- 未配置模型时不发送请求，界面说明原因。
- 成功返回时展示字段差异、证据状态、模型和提示词版本。
- 人工采纳后条目保持未确认，并产生可回溯审校事件。
- 失败、陈旧响应和未知字段不能修改当前条目。

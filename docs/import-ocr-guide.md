# 书论版本导入与 OCR：操作及维护

更新：2026-09-27。当前交付为本地服务功能；GitHub Pages 线上页面仍提示使用本地服务。

## 从哪里进入

古籍入库属于“材料准备”。工作台的“材料准备”区、快捷操作和侧栏都可进入；介绍／登录页与文件审核页也提供链接，进入完整工作区仍按原有规则登录。线上页面提供本地操作说明，PDF/OCR 处理由负责人在本机完成。已有 TXT、CSV、JSON 可以选择“导入已有材料”。

## 使用步骤

1. 在平台目录运行 `python3 server.py --host 127.0.0.1 --port 8765`，打开 `http://127.0.0.1:8765/index.html#ingest`。同一个数据目录只启动一个服务实例；若旧服务仍在运行，先确认没有任务执行，再重启加载新代码。
2. 在“导入书论 PDF”选择文件并导入，最大 512 MB。相同内容即使改了文件名，也会选中已有文件；加密、无有效页面或不完整的文件不会入库。原有 inbox 文件仍可选择。
3. 填写书名、版本／版次、来源，选择 PDF 起止页与页码偏移。书页 = PDF 页 - 偏移；本版处理的书页须大于 0，封面可跳过。版本字段可暂空，任务会显示未登记；正式材料应补全后建任务。
4. 保留“复用已有 TXT”和“OCR 缺失页”，创建任务。同一文件、范围、页码映射、资料和处理选项的重复请求返回已有任务。
5. 逐页查看扫描图并校对正文。展开“原始 OCR／复用文本”作对照，再点“保存文本”。编辑区保存的是校订稿，初稿独立保留；页面已被其他请求修改时会提示冲突并保留草稿，可重读页面后合并。
6. 在处理任务区查看失败原因，用“继续处理”重试失败页；已完成页不重做。服务意外中断后，重新启动会显示“已暂停”，点继续即可。校对草稿在翻页时保留，但未保存草稿不保证浏览器关闭后恢复，离开前应保存。
7. 下载全文 CSV 和处理清单，或点击“载入材料库”将页文本交给现有导入流程。确认导入后仍应检查材料库内容；原文文本进入材料库不等于专家已确认。
8. “生成候选”沿用已有主模型功能，需配置模型且会发生调用；本轮没有实际付费调用。正文变更会移除该页旧候选，需重新生成，最终仍须人工审核。

## 数据放在哪里

- 上传文件：配置的 inbox 下 `2026-09-27-shulun-platform-import/<PDF指纹>/`。原 PDF 不覆盖、不改写。
- 任务：默认 `.runtime/ancient-ingest/jobs/<任务ID>/`。`source-pages/` 为当前校订正文，`raw-pages/` 为首次处理结果，`ocr-manifest.json` 记录版本、页码、错误与修订，`pages.csv` 包含校订和初稿两份文本。
- 新页文件名：`page_<书页>__v<版本及页码映射标识>.txt`，与现有主表文件命名规则兼容。不同扫描版本不会因页码相同而混用。
- 原有未带版本标识的 `page_N.txt` 仅在可确定属于同一 PDF 的目录中复用；含多本不同 PDF 的混合目录不自动复用未标明归属的 TXT。建议一本书的 PDF 与逐页 TXT 独立放置。
- 旧任务兼容：可以继续读取原文件名；若历史初稿已被覆盖，平台显示“此历史任务未保留原始文本”，不会把校订稿假装成初稿。
- `CALLIGRAPHY_INBOX_ROOT` 和 `CALLIGRAPHY_INGEST_ROOT` 可指定隔离的输入与任务目录，供测试使用。不要让两个服务同时管理同一个任务目录。

## 验证与边界

执行 `npm test` 和 `npm run check`。本轮通过 161 项 JS、69 项 Python 测试；真实扫描切片 10 页（5 页复用、5 页 Tesseract OCR）已完成浏览器导入、保存、冲突保护、导出及桌面／手机检查。处理成功不表示文字识别准确率达标，仍须对原图人工校对。

没有集成独立 RapidOCR/API 试验工具，没有云 OCR、自动专家标注或生产迁移。本地保存与团队云端持久化是不同交付；共享材料及五人权限在阶段 2 验收。

回退：回退本轮业务代码及页面资源引用即可停用新入口，不删除 inbox 或 `.runtime` 文件；新任务和原始文本应保留以便恢复。不要恢复覆盖本轮之前已有的指导文档修改。

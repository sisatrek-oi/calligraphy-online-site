# 工作区版本冲突保护

Review date: 2026-09-14

## 依据与范围

继续 `2026-09-14-bulk-save-reliability.md` 的跨标签页覆盖检查。
项目入口依据工作区 Wiki `wiki/50-features/long-term-projects-map.md`；
实现与验证依据 `wiki/60-codex/workflow/ai-development-delivery.md`。
保持现有 UI，仅在版本冲突时出现与现有弹窗一致的提示。不提交、不部署、不改云端数据。

## 设计与复查

- 用两个隔离 VM 共享同一存储，复现旧页面将新页面的已确认记录覆盖为未确认。
- 每个页面保留实际载入或成功保存的工作区原始快照；保存前比较磁盘快照，
  不依赖事件是否及时送达，不仅比较时间戳，兼容旧备份格式及时间戳相同的修改。
- 序列化可能耗时，因此在生成保存内容后、真正写入前再核对一次。
  故障测试单独复现并覆盖了数据准备阶段另一页面写入的情况。
- 复查清空工作区的直接删除路径，补上同样检查，避免绕开保存入口删除新版数据。
- 正常操作失败回退继续由既有审校检查点处理。模板等旧路径可能保留本页未保存更改，
  但不能写回较新的工作区文件；冲突提示明确说明未保存，可先导出本页备份。

## 用户行为

- 检测到冲突时阻止写入，显示“工作区已更新/已移除”，不自动覆盖、不自动刷新。
- 提供导出本页备份及载入最新数据；备份不包含尚未提交的表单输入，弹窗明确提示。
- 载入最新数据需要再次确认，并固定读取发生冲突的工作区 ID，
  不因另一个页面切换了全局指针而误载入不同项目。
- 读取失败保留本页状态；成功后关闭旧表单和导入预览，清理过期详情请求。
- 弹窗限制 Tab 焦点循环，Escape/关闭恢复此前焦点；关闭弹窗不解除版本检查。
- 只针对冲突弹窗修正小屏关闭按钮宽度；主表和回检布局不变。

## 验证证据

- 新增 9 项测试；`npm test` 共 64 项 JavaScript、3 项 Python 测试通过，总计 67 项。
- 覆盖旧页面保存、批量/重置/删除/清空/字段保存、外部删除及损坏数据、
  同 ID 重新载入与重试、取消、时间戳未变化、只改变选中位置、备份、未知工作区、
  准备保存期间被另一页面更新、键盘焦点及关闭后重复尝试。
- `npm run check` 和 `git diff --check` 均通过；云端检查仍仅为静态结构检查。

## 剩余边界与下一步

- 这是乐观版本检查，不是跨进程原子比较交换；最后一次读取与写入之间仍有极短竞态。
  严格防止同时写入需进一步引入统一的异步锁/事务保存层，并验证所有调用者。
- 新建/切换工作区涉及数据键与全局指针的多键提交，仍需事务化和失败恢复专项测试。
- 旧版页面未加载新代码时不会主动遵守新保护，更新后需刷新旧页面。
- 云端全量同步、跨账号角色权限、版本锁、离线重试与合并未在本轮实现或实测。
- 只修改本轮函数、局部样式和测试；如需回滚，不能整体重置现有脏工作树。
